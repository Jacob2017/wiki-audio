# wiki-audio

A private podcast feed of [Paul Graham essays](https://paulgraham.com)
synthesized by ElevenLabs and served from Cloudflare R2 behind a
token-gated Worker. One CLI binary, one config dir, one cache dir,
one R2 bucket.

This README is the user/operator manual. The contributor manual is
`AGENTS.md`. The full design doc is `PLAN_FOR_AUDIO_LIBRARY.md` (in
the wiki content repo). The bead graph at `.beads/` is the
implementation plan.

> **Status:** v0.1.0 — Phase D extractor + chunker shipped; Phase E
> TTS + concat + ID3 in progress; Phase F publish + RSS feed pending.
> `wiki-audio init`, `doctor`, `build --dry-run`, `build --extract-only`,
> and `cost` are functional today; full `build` and `publish` land with
> Phase E/F.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/Jacob2017/wiki-audio/main/install.sh | bash
```

The installer auto-detects platform (linux/darwin × amd64/arm64),
fetches the matching tarball from GitHub Releases, **verifies SHA-256
against `checksums.txt`** (this is what makes the curl|bash line not
a supply-chain footgun), and drops the binary at `/usr/local/bin/`
(root) or `~/.local/bin/` (non-root, auto-`mkdir -p`).

```bash
# Pin a version
curl -fsSL https://raw.githubusercontent.com/Jacob2017/wiki-audio/main/install.sh | bash -s -- v0.1.0

# Manual (download from https://github.com/Jacob2017/wiki-audio/releases)
tar -xzf wiki-audio_0.1.0_linux_amd64.tar.gz && sudo mv wiki-audio /usr/local/bin/

# From source (Go 1.22+)
go install github.com/Jacob2017/wiki-audio/cmd/wiki-audio@latest

# In-place upgrade (re-runs install.sh against the current binary's path)
wiki-audio upgrade
```

ffmpeg is the only runtime dependency that isn't bundled — install
via `brew install ffmpeg` (macOS) or `apt install ffmpeg` (Debian-ish).
`wiki-audio doctor` checks for it.

## Quickstart

```bash
$ wiki-audio init
created /home/you/.wiki-audio/config.toml (with placeholders)
created /home/you/.wiki-audio/.env     (chmod 600, token generated)
next: edit config.toml and populate .env, then run `wiki-audio doctor`

WIKI_AUDIO_ACCESS_TOKEN generated:
  <43-char URL-safe token>
Mirror this value to:
  - 1Password (or whatever vault you use)
  - Cloudflare Worker secret: wrangler secret put ACCESS_TOKEN
```

Then:

1. **Edit `~/.wiki-audio/config.toml`** — set `[wiki].source_dir` to
   your essay directory, `[tts].voice_id` to an ElevenLabs voice ID,
   `[r2].account_id` + `bucket`, and `[feed].base_url` (your Worker
   URL). Required fields are documented in **Configuration reference**
   below.
2. **Populate `~/.wiki-audio/.env`** — add the three secrets (`ELEVENLABS_API_KEY`,
   `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`); the access token line
   was already generated by `init`. The file MUST stay `chmod 600`.
3. **`wiki-audio doctor`** — runs seven health checks (config valid,
   .env present + perms, ffmpeg in PATH, source dir has `.md` files,
   ElevenLabs auth + voice reachable, R2 bucket reachable, Worker
   token-gate contract). Each check prints `✓` or `✗` with a short
   status; exits non-zero on any failure.
4. **`wiki-audio build --dry-run`** — cost preflight. Walks the source
   dir, runs the extractor + chunker, prints per-essay char counts and
   a total credit estimate. No API calls, no file writes.
5. **`wiki-audio build`** — full pipeline: extract → hash check →
   chunk → TTS → concat → ID3 tag → place under
   `~/.cache/wiki-audio/out/<slug>.mp3`. Resumable via the local
   manifest mirror; a body_hash match in the manifest skips
   re-rendering.
6. **`wiki-audio publish`** — diff local against R2, upload new/changed
   MP3s, regenerate `pg.xml`, write `pg.manifest.json` back to R2.
7. **Subscribe** — paste `https://<your-worker>/pg.xml?t=<token>` into
   Pocket Casts (or any podcast app). Episodes auto-download.

Useful narrowing flags:

```bash
wiki-audio build --slug how-to-do-great-work       # one essay
wiki-audio build --extract-only --slug X           # print cleaned text, no synth
wiki-audio build --force                           # ignore hash skip
wiki-audio inspect --slug X                        # read-only diagnostics
wiki-audio cost                                    # per-tier credit estimate
```

## Daily flow

Once configured, adding a new essay is a two-command loop:

```bash
# Drop the new .md into [wiki].source_dir, then:
wiki-audio build && wiki-audio publish
```

`build` re-extracts every essay but only re-renders the new one (the
others' body_hash matches the manifest); `publish` only uploads the
new MP3 and regenerates `pg.xml`. Cost: ~$0.50 in EL credits per
PG-length essay added later.

The phone's podcast app polls the feed on its own schedule (typically
every 1–6 hours); the new episode appears without intervention.

## Configuration reference

`~/.wiki-audio/config.toml` is TOML, validated by
[`internal/config/loader.go`](internal/config/loader.go). Required
fields fail the load if absent; defaults from PLAN §2 are applied
when the field is the Go zero value.

```toml
[wiki]
# Absolute path to the directory containing source markdown.
# Each .md becomes one episode. REQUIRED; must exist + be a directory.
source_dir = "/home/you/dev/wiki/Wiki/raw/processed/paul-graham"

[tts]
# ElevenLabs voice ID. REQUIRED. PLAN §10 default is Christopher
# (G17SuINrv2H9FC6nvetn). Browse api.elevenlabs.io/v1/voices for more.
voice_id    = "G17SuINrv2H9FC6nvetn"
voice_label = "Christopher"          # display only; can be anything

# Optional — defaults shown:
# model_id             = "eleven_flash_v2_5"   # 0.5 credits/char (PG corpus default)
# chunk_max_chars      = 4000                  # per-request char budget; ElevenLabs caps at 5000
# request_timeout_s    = 60                    # per-chunk HTTP timeout
# retry_attempts       = 3                     # total per-chunk attempts incl. first
# retry_backoff_base_s = 2                     # exponential backoff base; jittered, capped at 60s
# output_format        = "mp3_44100_192"       # 192 kbps mono — A/B-validated for Christopher voice (PLAN §8.7); ~85 MB/hour

[r2]
# Cloudflare R2 account ID and bucket name. Both REQUIRED.
# Endpoint is derived: https://<account_id>.r2.cloudflarestorage.com
account_id = "abc123def456"
bucket     = "wiki-audio"

[feed]
# Public Worker URL fronting the R2 bucket. REQUIRED; must include scheme + host.
# Production hosts MUST use https:// for transport security.
base_url    = "https://wiki-audio.example.workers.dev"

# Recommended:
title       = "PG Essays"
description = "Paul Graham essays read aloud."
author      = "Paul Graham"
owner_email = "you@example.com"

# Optional:
# cover_image_url = "https://example.com/pg-cover.png"
# feed_path       = "pg.xml"      # default
# language        = "en-us"       # default
```

Forward-compat: TOML keys this binary doesn't recognize log a `WARN`
on load but don't fail. A typo in a key name surfaces visibly in the
log without locking out the run.

## Required env vars

`~/.wiki-audio/.env` is loaded via `godotenv`; the file MUST be
`chmod 600` (group/world-readable refuses to start). Values already
present in the shell env take precedence — useful for CI or for
overriding a single secret without editing the file.

| var | source | used by |
|-----|--------|---------|
| `ELEVENLABS_API_KEY` | https://elevenlabs.io/app/settings/api-keys | `wiki-audio build` (TTS calls), `wiki-audio doctor` (auth check) |
| `R2_ACCESS_KEY_ID` | Cloudflare → R2 → Manage API Tokens | `wiki-audio publish` (S3 uploads), `wiki-audio doctor` |
| `R2_SECRET_ACCESS_KEY` | same | same |
| `WIKI_AUDIO_ACCESS_TOKEN` | generated by `wiki-audio init` (43-char URL-safe random) | embedded into feed enclosure URLs at gen time; the Worker validates it on every fetch |

Optional / informational:

- `R2_TOKEN` — some Cloudflare client paths use this; minio-go (our
  R2 client) does not. Safe to leave unset.
- `CLOUDFLARE_API_TOKEN` — needed by `wrangler` for token rotation
  (`wrangler secret put ACCESS_TOKEN`), not by `wiki-audio` itself.
  Set it in your shell when running rotation steps; not required in
  `.env`.

`wiki-audio doctor` reports any missing required vars by name with
the offending env var quoted. Empty values (`KEY=`) are treated as
missing — `init` generates non-empty placeholders.

## Token rotation

`WIKI_AUDIO_ACCESS_TOKEN` is the static random token the Worker
validates on every feed/episode fetch. Rotate it when you suspect
the URL leaked (screenshot, shared screen, bot scrape).

The canonical step-by-step runbook lives in
[`worker/README.md` § Secret rotation](worker/README.md#secret-rotation).
Short version:

1. Generate a fresh 43-char token (`openssl rand -base64 32 | tr '+/' '-_' | tr -d '='`).
2. `wrangler secret put ACCESS_TOKEN` (push to Cloudflare Worker).
3. Edit `~/.wiki-audio/.env` `WIKI_AUDIO_ACCESS_TOKEN=<new>`.
4. Mirror the new value to 1Password.
5. `wiki-audio publish --feed-only` (regenerates feed enclosure URLs
   with the new token).
6. Re-paste the new feed URL into Pocket Casts.

Old token → 403 immediately (no R2 object renames needed; the token
lives in the query string, not the path).

## Where things live

wiki-audio writes to two directories on the local machine and one R2
bucket. Knowing which is which answers most "where does X live?"
questions without grepping the codebase.

### `~/.wiki-audio/` — config + secrets

Operator-edited configuration. Contains:

| file | purpose |
|------|---------|
| `config.toml` | TOML config (source dir, voice id, R2 endpoint, feed metadata). Mode `0o644`. |
| `.env` | Secrets — `ELEVENLABS_API_KEY`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `WIKI_AUDIO_ACCESS_TOKEN`. Mode `0o600`; a fail-closed startup check refuses to run if `mode & 0077 != 0`. |

`wiki-audio init` scaffolds both. The `.env` write is atomic (`internal/atomic`,
wa-76r.2) so a crash mid-rotation cannot leave a half-written file in place.
The `--env-local` flag points at `.env` in the current working directory
instead, useful for ephemeral / per-project overrides.

### `~/.cache/wiki-audio/` — regeneratable build output

Per-essay TTS intermediates and finalized MP3s awaiting publish.
Regeneratable from source — safe to `rm -rf` if disk pressure hits.
XDG-aware: when `$XDG_CACHE_HOME` is set, the base is
`$XDG_CACHE_HOME/wiki-audio/` instead of `$HOME/.cache/wiki-audio/`.

```
~/.cache/wiki-audio/
├── tmp/<slug>/<index>.mp3   per-chunk TTS intermediates
├── out/<slug>.mp3           final concatenated MP3 awaiting publish
└── skipped.txt              one slug per line — malformed essays
```

| path helper | contents | mode |
|-------------|----------|------|
| `cache.TmpDir(slug)` | `tmp/<slug>/0.mp3`, `tmp/<slug>/1.mp3`, … one file per chunk emitted by the §5.3 ElevenLabs client. | `0o755` |
| `cache.OutPath(slug)` | `out/<slug>.mp3` — the final concatenated essay produced by `internal/concat`. The publish pipeline reads from this path and uploads to R2. | `0o755` |
| `cache.SkippedPath()` | `skipped.txt` — append-only log of essays that failed §6 sanity checks (e.g. `CharCount < 200` after extraction). One slug per line. | `0o644` |

#### Cleanup policy (§6)

- **`tmp/<slug>/`** — removed by `cache.CleanupTmp(slug)` after a
  successful concat. On concat **failure** the directory is preserved
  intact so an operator can rerun `ffmpeg` by hand against the raw
  chunk MP3s without paying for re-synthesis.
- **`out/<slug>.mp3`** — kept by default after publish for fast
  re-upload on token rotation (`wiki-audio publish` is idempotent;
  unchanged body_hash skips the upload). `cache.CleanupOut(slug)`
  exists for operators who hit disk pressure; the publish pipeline
  does NOT call it automatically.
- **`skipped.txt`** — never auto-cleaned. The accumulated list helps
  spot extractor regressions across runs (an essay that started
  appearing here after a recent change suggests a parser bug).

#### Disk footprint

For the v1 corpus of 53 PG essays the steady-state on-disk footprint
is roughly:

- `tmp/` peak: ~50 MB during a bulk build (one essay at a time, ~15
  chunks × ~1 MB each). Cleared after each successful concat.
- `out/` steady-state: **~3.6 GB** across all 53 finalized MP3s
  (~70 MB/essay at the default 192 kbps mp3_44100_192 profile —
  see PLAN §8.7 for the empirical-A/B rationale).
- `skipped.txt`: kilobytes at most.

Plan ~5 GB headroom on the cache filesystem before a bulk build (3.6
GB final + tmp peak + slack).

### Cloudflare R2 — source of truth for published state

| key | purpose |
|-----|---------|
| `pg.manifest.json` | Per-episode metadata keyed by slug (body_hash, voice_id, model_id, char_count, R2 key, generated_at, published_at). The publish path's diff anchor — episodes whose body_hash matches a stored entry are skipped on rebuild. |
| `pg.manifest.json.bak` | Previous manifest, written before each save. Cheap recovery if the latest manifest is somehow corrupted. |
| `pg.xml` | The RSS feed (iTunes namespace, generated by `internal/feed`). The URL operators paste into Pocket Casts. |
| `pg/<slug>.mp3` | The episode enclosures referenced by the RSS feed. Served via the Worker; URLs include `?t=<WIKI_AUDIO_ACCESS_TOKEN>`. |

The R2 bucket itself has **zero public access** — every read goes
through the Cloudflare Worker, which gates on a constant-time token
compare. See `worker/README.md` for the 403/403/404 contract and the
threat-model context.

The manifest schema carries an integer `version` field; bumping
`model.ManifestSchemaVersion` (and the mirrored `manifest.KnownManifestVersion`)
in the same PR that adds a field is the supported migration path.
Older binaries reading a newer manifest fail closed at write-time
(`manifest.ErrSchemaTooNew`) rather than silently dropping unknown
fields. See wa-76r.1.
